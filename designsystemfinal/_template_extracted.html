02

Audit & Principles

Honest read on what's working, what isn't, and the rules we'll use to judge every new decision.

Before
97
1 2 3 4
  1. 1Monochrome purple saturation — every icon, accent, chart, and CTA is the same hue. Hierarchy collapses, nothing earns attention.
  2. 2Hero card is a different design system — dark gradient block with inverted type fights the rest of the page.
  3. 3KPI cards are decorative, not informative — colored icon tiles, no trend, no comparison, numbers float unanchored.
  4. 4Three different card styles coexist — rounded cards, outlined cards, and a dark hero. No shared container grammar.
  5. 5Emoji as data signal — 🔥 next to "hot leads" is friendly but crowds out the number itself.
  6. 6Navigation noise — all-caps section labels + full-color icons + colored active-pill create three competing visual weights in one rail.
Principles
01

One number at a time

Every screen answers one question first. Everything else is supporting evidence, smaller and quieter.

02

Rhythm over ornament

Consistent vertical rhythm and a small set of spacing steps. Decoration never replaces hierarchy.

03

Color is signal

Neutral surfaces do the layout work. Accent colors mean action, success, warning — never "decorative."

04

Dense, not cramped

SDRs scan hundreds of rows per shift. Breathing room comes from type and line-height, not reduced information.

05

Keyboard parity

Every primary action has a shortcut. Visible focus states. No interaction that requires a mouse.

06

Accessible by default

WCAG AA minimum on all text. Semantic color never the only carrier of meaning — always paired with a label or glyph.

03

System Foundations

Color as role, not as paint. A type scale that carries hierarchy by itself. Spacing, radius, elevation, motion — each defined as a short, memorizable set.

Component Patterns

The production set. Each ships with a single default, explicit variants, and a rule for when not to use it.

4.1

Buttons

One primary per view. Size by context: sm in dense tables, md default, lg in empty states and auth only.

Do

Lead with a verb. "New mission," "Export CSV," "Call now."

Don't

Don't put two primaries side-by-side. The second one must be secondary or ghost.

4.2

Inputs & forms

Label above field always. Helper text on a separate line. Error state replaces helper, never stacks on top of it.

Handoff & Rollout

Concrete guidance for the team. Tokens to ship, components to map, an order that minimizes user disruption.

Ship as a single tokens.json consumed by Tailwind config and a CSS custom-properties file. Dark mode is a sibling theme file — same role names, different values.

Rollout plan

  1. Phase 1 · Week 1–2
    Tokens & primitives
    Ship tokens.json, DM Sans/Mono via @font-face, reset button/input/badge/avatar. No visual change to users yet — all legacy components still render. Behind ?ds=v2 flag.
  2. Phase 2 · Week 3–4
    Navigation + dashboard
    Replace sidebar and top dashboard. Highest visual impact, lowest risk — no destructive actions on these screens. Gather feedback from 10 SDRs in a design-partner cohort.
  3. Phase 3 · Week 5–7
    Lists, detail, call console
    The daily driver for SDRs. Ship with a "restore old UI" escape hatch for two weeks. Track time-to-complete for core tasks before/after.
  4. Phase 4 · Week 8
    Settings, auth, onboarding, dialogs
    Lower-traffic surfaces. Remove ?ds=v2 flag. Retire old component files. Publish v2 docs site.
  5. Phase 5 · Week 9–10
    Dark mode + mobile polish
    Command Deck (direction C) ships as optional dark theme. Mobile call console refined with thumb-zone buttons and larger hit targets.

Migration rules for engineers

  • Never hard-code hex. Use var(--color-*).
  • Never hard-code px spacing outside the 10-step scale. Use var(--space-*) or Tailwind px-{step}.
  • Buttons: exactly one --primary per view. ESLint rule to flag violations.
  • Icon size: 14 inside buttons, 16 in nav, 20 in empty states. No other sizes.
  • Every interactive element must render a :focus-visible state using --focus-ring.
  • No new component without a doc entry and a dark-mode variant.

Success metrics

  • Time-to-first-call for a new SDR on day 1: target − 40%.
  • Dashboard scan time (eye-tracking): target − 25%.
  • Accessibility audit: 100% WCAG AA on all shipped surfaces.
  • Support tickets mentioning "can't find" / "hard to read": target − 50% in 90 days.
  • Component sprawl: 63 legacy components → 24 system components.
End of spec
A system is only as good as its enforcement. Ship the tokens, the lint rules, and the doc site in the same week — otherwise v2 becomes v1.5 plus opinions.
